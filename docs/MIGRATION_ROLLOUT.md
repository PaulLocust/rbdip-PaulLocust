# Разделение имени клиента без остановки API

Для новой пустой БД обычный запуск применяет V1–V4. Для работающей БД
expand и contract нужно разнести между развёртываниями приложения.

1. На версии ЛР2 применить миграции только до V3 (`SPRING_FLYWAY_TARGET=3`).
   V3 добавляет поля и заполняет существующие записи. Триггер синхронизирует
   запись старого `full_name` и новых `first_name`/`last_name` в обе стороны.
2. Развернуть версию ЛР3 с тем же ограничением `SPRING_FLYWAY_TARGET=3`.
   Она читает и записывает только новые колонки, а триггер поддерживает старую.
   Во время обновления старые и новые экземпляры могут работать вместе.
3. Проверить, что старые экземпляры и фоновые задачи остановлены, новые
   обслуживают запросы, поля заполнены. До contract возможен откат приложения
   к версии ЛР2 без обратной миграции данных.
4. Применить V4 отдельным процессом Flyway, сняв ограничение target.
   Она удаляет триггер и `full_name`. Новые экземпляры продолжают работать.
   После этого откат на ЛР2 требует восстановления совместимой схемы.

DDL требует краткой блокировки PostgreSQL. `lock_timeout=5s` ограничивает
ожидание блокировки; при конфликте миграция откатывается и повторяется позже.
Это отсутствие остановки сервиса, а не обещание нулевой задержки запросов.
Для большой таблицы backfill нужно выполнять порциями в отдельном шаге;
здесь используется одна транзакция для небольшой учебной БД.

Имя делится по первому пробелу, остальная часть сохраняется целиком.
Для имени из одного слова `last_name` — пустая строка. Исходные пробелы
сохраняются, чтобы ответ API не менялся после миграции.

Проверки:

- `CustomerNameMigrationTest`: заполненная БД, составные имена, одно слово,
  пробелы, вставки и изменения старой и новой версией, затем contract.
- `LoadDuringMigrationReferenceTest`: чтение старого поля одновременно с expand.
- `ApiMigrationLoadTest`: четыре потока создают и читают заказы через HTTP
  до, во время и после contract. Ошибки запросов и неполные данные проваливают тест.

Запуск: `mvn test -Dtest=CustomerNameMigrationTest,LoadDuringMigrationReferenceTest,ApiMigrationLoadTest`.
